# 参考调查（2026-11-01）：现有实现与可借鉴处

结论先说：**没有一个现成参考能直接当作多用户高并发的网页控 agents 架构**，
v0.2 是在下面这些参考的模式上、按 MolaTube 的约束重做的，不照搬任何一份代码。

## 1. 本地已有的

### MolaTube v0.1（本仓库，`server/index.mjs`）
- 已有：内存队列、Worker 池上限 3、每用户同时跑 1 个、每任务独立工作区、审计日志。
- 缺口：状态只在内存（重启即丢）、Worker 与主进程同进程（一个任务卡死/崩溃会拖垮全部）、
  无实时推送（前端 2 秒轮询）、只有一次性任务、没有 agent 生命周期（暂停/重试/备注）。
- v0.2 保留它的 API 形状（`/api/jobs` 兼容），其余按第 2 节重做。

### DeepSeek Harness（dsh，`@deepseek-ai/dsh`）
- 形态：Cordis 插件式 agent harness，`dsh web` 在本地 127.0.0.1:3080 提供 Web UI，
  插件以 bundle 形式接入，支持 OpenAI 兼容 provider。
- 现状：2026-10-28 装过 0.2.1-rc.2，当晚用户弃用；本机只剩 `~/.dsh/`（profiles/storages/logs），
  二进制已随 VM 替换消失。**不复活 dsh，只借鉴“插件 bundle + 本地 Web 控制面”的形态。**
- 可借鉴：插件化任务类型、Web 控制面与执行面分离。

### LayerFS（含 `dsh-layerfs` 集成）
- 核心模式：每个 agent 一个可写 Workspace，落在共享已提交历史之上，不复制整棵基线；
  检查点内容去重，可分支/回退/合并。JS SDK 为仓内私有包，未发 npm。
- 本地另有 magpie-layerfs 的 sim 后端：SHA-256 内容寻址 + 分支清单 + 去重检查点。
- v0.2 借鉴：**工作区 = 每 agent 运行一份独立目录 + 输入快照 + 产物**，先用文件系统实现，
  未来可把目录换成 LayerFS Workspace 而不改控制面接口。

## 2. dsh-superagent-prototype（deepseek-ai，2026-10-31 当天发布）
- 定位：**研究原型，作者明言非生产代码**，单仓库主动式编码 agent，以 DSH bundle 打包；
  监听 GitHub/飞书，有人允许时开 work item，在自己的 agent session 与目录里干活，
  Web 面板只展示需要人处理的事。
- 借鉴的模式（只借模式，不抄代码）：
  - **Engine 单写者**：状态变更走同步命令、每命令一个事务；外部工作先进端口队列、提交后再由适配器执行。
  - **Runtime 组合根**：启动时锁状态目录、恢复被打断的 Assignment；关闭时取消 turn、等齐、再释放锁。
  - **Passes 节律**：每 2 秒一轮 + 按需触发，评估到期项；前端轮询是它的兜底，SSE 是我们的主通道。
  - **Outbox 回执**：消息回执与后续 effect 在同一事务里记账，源离线时消息等待、会话消失时丢弃。
  - **Panel 三问**：打开面板先回答“有什么需要我？系统健康吗？一件活的历史是怎样的？”；
    标签按 Overview / Source / Trigger / Eval / Execution / Settings 分工，**一个概念只在一个地方**；
    状态必须诚实（数字等于它链接的列表长度）、默认安静、有问题的行直接给动作、破坏性动作需确认。
  - **人的控制**：stop / retry / note / requestStatus，等待人的 Ticket 明确标出在等谁。
- **不采纳处**：它是单仓库、单团队、研究代码，没有多用户并发、配额、隔离与支付概念；
  它的 Eval/接纳规则（GitHub/飞书触发）与 MolaTube“用户主动发起”约束冲突，不引入。

## 3. newapi（用户早前提及，仅作支付层参考）
- 只借“多渠道支付抽象”一层：`PaymentProvider` 接口 + 各渠道独立配置，默认关闭。
- 不进入本架构的核心：支付不决定任务能否跑，更不按学习结果定价。

## 4. 由此定出的 v0.2 取舍
- 控制面与执行面分离：HTTP/SSE 只做状态与控制，真正干活的在子进程 Worker 里。
- 状态单写者 + 磁盘快照 + append-only 事件日志，重启后中断状态诚实标出，不假装成功。
- 并发靠“队列 + Worker 池 + 三级上限”而不是无限制起进程；背压靠队列上限与明确排队位置。
- 工作区先用目录隔离 + 路径监狱，接口上预留未来换 LayerFS Workspace 的位置。
