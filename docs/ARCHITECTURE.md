# MolaTube Agent Harness 架构：高并发、独立工作区、安全

> 原则先行：所有 Agent 任务必须由用户主动发起。Harness 不接受“替我刷完”
> 这类目标，任务描述里出现第三方平台代刷、代考意图时直接拒绝。

## 1. 组件

```
浏览器 / 客户端
  → API 网关（鉴权、限流、审计）
    → 任务队列 JobQueue（FIFO + 每用户公平队列）
      → Worker 池（固定并发上限，可横向扩展）
        → 工作区 WorkspaceManager（每任务一个目录）
        → 浏览器池 BrowserPool（每任务一个独立上下文）
      → 审计日志 AuditLog（只记动作与结果，不记凭证与正文以外的隐私）
```

## 2. 高并发

- 队列：全局 FIFO 叠加每用户公平轮转，避免单个用户占满 Worker。
- 背压：队列满时返回“排队中”而不是无限接单；前端显示排队位置。
- Worker 池：默认并发 3（`MAX_WORKERS`），CPU/内存/时长配额 per 任务。
- 幂等：同一用户对同一视频的同一任务类型去重，已有进行中任务直接返回它。
- 取消：用户随时取消，Worker 收到取消信号后停掉子步骤并清理工作区。

## 3. 独立工作区

- 每个任务一个目录：`server/workspaces/<jobId>/`，内含输入快照、中间产物、结果。
- 隔离规则：
  - Worker 只能读写自己任务的目录，路径穿越直接拒绝。
  - 浏览器上下文 per 任务：独立 Cookie/Storage，任务结束即销毁，绝不复用。
  - 跨任务、跨用户读取默认拒绝；分享只能由用户显式导出自己的结果。
- 清理：任务完成/取消/超时后按保留期清理工作区，只留结果摘要与审计行。

## 4. 安全

| 风险 | 缓解 |
| --- | --- |
| 跨用户数据泄露 | 工作区按 jobId 隔离 + API 按用户鉴权 + 路径白名单 |
| 会话/凭证泄露 | 凭证只存于任务工作区的临时文件，不进日志、不进结果、不跨任务复用 |
| 资源耗尽 | 每任务 CPU/内存/时长配额 + 全局并发上限 + 超时强杀 |
| 提示注入（视频标题、简介、评论都视为数据） | 外部文本只当数据引用，绝不当中控指令；工具调用需任务白名单 |
| SSRF / 内网探测 | 出站只允许配置的白名单域名，内网地址段直接拒绝 |
| 支付滥用 | 支付只用于会员与增值功能（newapi 式渠道抽象），不卖学习结果；金额与订单号全程审计 |

## 5. 支付（预留，不默认开启）

- 渠道抽象：`PaymentProvider` 接口（微信/支付宝/ Stripe 等），各渠道独立配置。
- 默认关闭：未配置渠道时前端不展示支付入口，后端拒绝创建订单。
- 绝不出现“按刷课时长/按通过收费”这类定价。

## 6. v0 实现状态

- `server/index.mjs` 是零依赖骨架：队列、Worker 池、工作区、审计都已跑通，
  任务执行步目前是本地模拟步骤，真实 LLM/浏览器步骤在 `runTask()` 处接入。
- 前端在后端不可达时自动降级为本地演示模式，不伪造后端结果。
